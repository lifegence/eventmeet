# Google Workspace 設定手順書

EventMeet ─ 社内ミーティングの Google Meet 連携

対象: EventMeet 0.1.0 以降（Frappe v15 / v16）。読者: Google Workspace 特権管理者、Google Cloud 管理者、Frappe システム管理者。

[English](../en/google-meet-setup.md)

## 1. 概要

### 1.1 目的

本書は、EventMeet の社内ミーティングで Google Meet を使うために必要な、Google Cloud・Google Workspace・Frappe の設定手順をまとめたものです。セミナー（社外向け）は Zoom を使うため、本書の対象外です（[Zoom セミナー設定・運用手順書](zoom-seminar-guide.md) を参照）。

### 1.2 連携の仕組み

- Frappe はサービスアカウントを使い、「ドメイン全体の委任」により**主催者本人として** Google API を呼び出します。
- 社内ミーティングを保存すると、主催者の Google カレンダーに Google Meet 付きの予定が作成されます（この時点では参加者に通知しません）。
- 「招待を送信」を押すと、Google カレンダーから参加者に招待が届きます。以後の日時変更・中止も Google から通知されます。
- 会議の終了後、Meet の会議記録から参加者と参加時間を取り込みます。参加者のメールアドレスは People API で特定します。
- 任意で、Gemini の「自動メモ作成」で作られた Google ドキュメントを「AI 要約 / 会議メモ」に取り込みます。Meet の「文字起こし」（全文の記録）は取り込みの対象外です。

### 1.3 利用する API と権限（スコープ）

| API | スコープ | 用途 | 要否 |
|---|---|---|---|
| Google Calendar API | `calendar.events` | 予定と Meet の作成・変更・中止、招待の送信 | 必須 |
| Google Meet REST API | `meetings.space.readonly` | 会議記録・参加者・参加時間・会議メモの取得 | 必須 |
| People API | `directory.readonly` | 参加者 ID からメールアドレスを特定 | 必須 |
| Google Drive API | `drive.readonly` | Gemini の会議メモ（ドキュメント）の取り込み | 任意 |

スコープの正式な値（`https://www.googleapis.com/auth/...`）は付録 A にまとめています。

### 1.4 作業する画面と担当

作業は 3 つの別々の画面で行います。**Google Cloud コンソールと Google 管理コンソールは別のサイト**です。取り違えると、目的のメニューが見つからなかったり、有料サービスの案内が表示されたりします。

| 手順 | 作業する画面（URL） | 担当 | 必要な権限 |
|---|---|---|---|
| 3.1〜3.4 プロジェクト、API、サービスアカウント、鍵 | **Google Cloud コンソール**<br>`console.cloud.google.com` | Google Cloud 管理者 | プロジェクト作成、サービスアカウントと鍵の管理 |
| 3.4 組織ポリシーの例外（必要な場合のみ） | **Google Cloud コンソール** | Google Cloud 組織の管理者 | 組織ポリシー管理者 |
| 3.5〜3.7 ドメイン全体の委任、ディレクトリ、Gemini | **Google 管理コンソール**<br>`admin.google.com` | Google Workspace 管理者 | 特権管理者 |
| 3.8 EventMeet の設定 | **Frappe**<br>`https://<サイト>/app/conferencing-settings` | Frappe 管理者 | System Manager または Seminar Manager |

> [!WARNING]
> Google Cloud コンソールの左メニューにある「Security」（Security Command Center）は有料のセキュリティサービスで、本書の作業には不要です。料金プランや試用の画面が表示されても、開始ボタンは押さないでください。

## 2. 事前確認チェックリスト

| 確認 | 項目 |
|---|---|
| □ | Google Workspace の特権管理者アカウントを利用できる |
| □ | Google Cloud コンソールに Workspace の組織アカウントでログインできる |
| □ | 主催者となる Frappe ユーザーのメールアドレスが、Workspace アカウント（例: taro@example.com）と一致している |
| □ | Frappe サイトに EventMeet（0.1.0 以降）がインストールされている |
| □ | （Gemini メモを取り込む場合）Workspace で Gemini の「自動メモ作成」を利用できる |

## 3. 設定手順

### 3.1 Google Cloud プロジェクトを作成する

> **画面:** Google Cloud コンソール（`https://console.cloud.google.com/`）

1. Google Cloud コンソールに、Workspace の組織アカウントでログインします。
2. 画面上部のプロジェクト選択から「新しいプロジェクト」を選びます。
3. プロジェクト名（例: eventmeet）を入力し、「組織」と「場所」に自社の Workspace 組織を選んで「作成」を押します。

> [!NOTE]
> 既存のプロジェクトも使えますが、権限を分けて管理するため、この連携専用のプロジェクトをおすすめします。

### 3.2 API を有効にする

> **画面:** Google Cloud コンソール

1. 3.1 で作成したプロジェクトを選択した状態で、「API とサービス」→「ライブラリ」を開きます。
2. 次の API を検索し、それぞれ「有効にする」を押します。

| API 名 | 要否 |
|---|---|
| Google Calendar API | 必須 |
| Google Meet REST API | 必須 |
| People API | 必須 |
| Google Drive API | 任意（Gemini メモを取り込む場合） |

### 3.3 サービスアカウントを作成する

> **画面:** Google Cloud コンソール

1. 「IAM と管理」→「サービスアカウント」→「サービスアカウントを作成」を押します。
2. サービスアカウント名（例: `eventmeet-google`）と説明を入力し、「作成して続行」を押します。
3. ロールの付与（プロジェクトへのアクセス権）は不要です。そのまま「完了」を押します。
4. 一覧から作成したサービスアカウントを開き、「詳細」タブの「一意の ID」（数字の ID）を控えます。これが 3.5 で入力する「クライアント ID」です。

> [!NOTE]
> Workspace のデータへのアクセス範囲は、3.5 のドメイン全体の委任で決まります。Google Cloud 側のロールは必要ありません。

### 3.4 JSON 鍵を作成する

> **画面:** Google Cloud コンソール

1. サービスアカウントの「鍵」タブで「鍵を追加」→「新しい鍵を作成」を選びます。
2. キーのタイプに「JSON」を選んで「作成」を押すと、JSON ファイルがダウンロードされます。
3. このファイルは 3.8 で Frappe に登録した後、端末から削除します。メール、チャット、共有ドライブには置かないでください。

> [!WARNING]
> 「サービス アカウント キーの作成が無効になっています」と表示された場合:
>
> 2024年5月3日以降に作成された Google Cloud 組織では、組織ポリシー `iam.disableServiceAccountKeyCreation`（新しい名称では `iam.managed.disableServiceAccountKeyCreation`）が既定で適用され、鍵を作成できません。
>
> 組織ポリシー管理者が「IAM と管理」→「組織のポリシー」で、このプロジェクトに限りポリシーを上書き（適用しない）してから、手順 1 からやり直します。
>
> 鍵の作成後はポリシーを元に戻して構いません。作成済みの鍵は引き続き使えますが、鍵を差し替えるときは再度の例外設定が必要です。

### 3.5 ドメイン全体の委任を設定する（特権管理者）

> **画面:** **Google 管理コンソール**（`https://admin.google.com/`）。Google Cloud コンソールではありません。

1. ブラウザの新しいタブで、Google 管理コンソールに**特権管理者**でログインします。右上のアカウントが特権管理者になっていることを確認してください（複数のアカウントでログインしていると、別のアカウントで開くことがあります）。
2. 次の URL を開きます。メニューから開く場合は、メニュー →「セキュリティ」→「アクセスとデータ管理」→「API の制御」を開き、ページの一番下にある「ドメイン全体の委任を管理」を押します。

```
https://admin.google.com/ac/owl/domainwidedelegation
```

3. 「新しく追加」を押します。
4. 「クライアント ID」に、3.3 で控えた一意の ID を入力します。
5. 「OAuth スコープ（カンマ区切り）」に次の文字列を貼り付け、「承認」を押します。

```
https://www.googleapis.com/auth/calendar.events,https://www.googleapis.com/auth/meetings.space.readonly,https://www.googleapis.com/auth/directory.readonly
```

Gemini の会議メモを取り込む場合は、末尾に次を追加します。

```
,https://www.googleapis.com/auth/drive.readonly
```

> [!NOTE]
> 設定の反映には最大 24 時間かかることがあります（通常はもっと早く反映されます）。
>
> 「API の制御」の画面上部に、上位プランの機能やアップグレードの案内が表示されることがあります。ドメイン全体の委任には関係ないので、無視して構いません。

> [!WARNING]
> 委任したスコープの範囲で、サービスアカウントは組織内の全ユーザーのデータにアクセスできます。本書に記載したもの以外のスコープは追加しないでください。

### 3.6 ディレクトリの連絡先共有を確認する

> **画面:** **Google 管理コンソール**（`https://admin.google.com/`）

参加ログの照合で、People API から参加者のメールアドレスを取得するための設定です。

1. Google 管理コンソールで、左上の「≡」（メニュー）を押して左メニューを表示します。
2. 「ディレクトリ」を押して中の項目を開き、「ディレクトリ設定」を開きます。見つからない場合は、画面上部の検索ボックスに「連絡先の共有」と入力し、表示された候補から開きます。
3. 「共有設定」の「連絡先の共有」がオンになっていることを確認します（オフならオンにします）。
4. 同じ画面の「外部ディレクトリの共有」で、API からドメインのプロフィールを参照できる設定になっていることを確認します。

> [!NOTE]
> 左メニューに「ディレクトリ」が無い場合は、Google Cloud コンソールを開いていないか（URL が `admin.google.com` か）、特権管理者でログインしているかを確認してください。
>
> この共有が無効でも、会議の作成と招待は動作します。ただし参加ログは表示名での照合になり、同姓同名や表示名の違いがあると照合できません。

### 3.7 Gemini の会議メモを取り込む（任意）

Meet の「自動メモ作成」（Take notes for me）を使うと、会議の後に要約の Google ドキュメントが作成されます。これを EventMeet に取り込むには、次の 3 か所を設定します。

| No. | 作業する画面 | 設定 |
|---|---|---|
| 1 | Google 管理コンソール | Google Meet の Gemini による会議メモ機能が、対象ユーザーに有効になっていることを確認する |
| 2 | Google Cloud コンソール／Google 管理コンソール | 3.2 で Google Drive API を有効にし、3.5 で `drive.readonly` を委任していることを確認する |
| 3 | Frappe（3.8 で実施） | オンライン会議設定の「Gemini の会議メモを取り込む」をオンにする |

会議では、主催者または参加者が会議中に「自動メモ作成」を開始します。開始しなかった会議には要約ドキュメントが作られないため、取り込まれません。

> [!WARNING]
> Meet の「文字起こし」（Transcript、発言の全文）は取り込みの対象外です。EventMeet が取り込むのは「自動メモ作成」の要約ドキュメントだけです。

### 3.8 Frappe（EventMeet）を設定する

> **画面:** **Frappe**（`https://<サイト>/app/conferencing-settings`）

1. Frappe に System Manager（または Seminar Manager）でログインし、「オンライン会議設定」を開きます。上部の検索バーで「オンライン会議設定」と検索しても開けます。
2. 「Google Meet」の欄で「**Google Meet を有効化**」にチェックを入れます。チェックを入れると、その下に Google の設定項目が表示されます（チェックを入れるまでは表示されません）。
3. 次の項目を設定して保存します。

| 欄 | 項目（画面の表示） | 設定値 |
|---|---|---|
| Google Meet | Google Meet を有効化 | オン |
| Google Meet | Workspace ドメイン | 自社のドメイン（例: example.com）。複数ある場合はカンマ区切り |
| Google Meet | サービスアカウント鍵（JSON） | 3.4 でダウンロードした JSON ファイルの中身をすべて貼り付け |
| Google Meet | Gemini の会議メモを取り込む | 3.7 を実施した場合のみオン |
| 既定 | 社内ミーティングの会議ツール | 社内ミーティングの既定を Google Meet にする場合は「Google Meet」 |

4. 保存できたら、JSON ファイルを端末から削除します。
5. 主催者になる各ユーザーについて、Frappe のメールアドレスが Workspace アカウントと一致していることを確認します。

> [!NOTE]
> 鍵は Frappe 内で暗号化して保存され、画面には「*****」と表示されます。鍵を差し替えるときは、新しい JSON を貼り直して保存します。
>
> 既定のツールを変更しても、作成済みの社内ミーティングは元のツールのまま変わりません。

## 4. 動作確認

テスト用の社内ミーティング（「社内ミーティング」→「新規」）で、次の順に確認します。

| No. | 操作 | 期待する結果 |
|---|---|---|
| 1 | 社内ミーティングを新規作成して保存する（オンライン会議: オン、会議ツール: Google Meet、参加者: 1 名以上） | 「参加 URL」に Meet の URL が入る。主催者の Google カレンダーに予定が作成される。参加者にはまだ通知されない |
| 2 | 「招待を送信」を押す | 参加者に Google カレンダーの招待メールが届き、参加者のカレンダーに予定が入る。ステータスが「招待済」になる |
| 3 | 日時を変更して保存する | 参加者に Google から変更の通知が届く |
| 4 | 会議を実施する（主催者と参加者が Meet に参加）。AI 要約も確認する場合は、会議中に「自動メモ作成」を開始する | ─ |
| 5 | **予定終了時刻**から 15 分以上たってから確認する（取り込みは 10 分ごとに自動実行）。すぐに確認したい場合は「Google Meet」→「参加ログを取得」を押す | 「参加者」の出席と参加時間（分）が更新される |
| 6 | （任意）「議事録」タブを開く | 取り込み前は「AI 要約 / 会議メモ」の見出しと、取り込み時期の案内が表示される。予定終了時刻の約 15〜25 分後以降に要約が表示される。議事録が空の場合は、要約が下書きとして議事録にもコピーされる |
| 7 | ステータスを「中止」にして保存する | 予定が削除され、参加者に Google から中止の通知が届く（招待を送信済みの場合） |

> [!NOTE]
> 取り込みは「会議が実際に終わった時刻」ではなく、社内ミーティングに入力した「終了日時」（予定終了時刻）を基準に始まります。予定より早く終えた場合も、予定終了時刻の 15 分後までは取り込まれません。

## 5. トラブルシューティング

エラーの詳細は、Frappe の「エラーログ」一覧で確認できます。

| 症状・エラー | 主な原因 | 対処 |
|---|---|---|
| Google Cloud コンソールで料金プラン（Security Command Center など）が表示される | Google 管理コンソールではなく Google Cloud コンソールで「Security」を開いた | 3.5・3.6 は `admin.google.com` で行う（1.4 を参照）。有料プランは開始しない |
| 管理コンソールに「ディレクトリ」や「ドメイン全体の委任」が見当たらない | Google Cloud コンソールを開いている、または特権管理者でない | URL が `admin.google.com` か、右上のアカウントが特権管理者かを確認する。3.5 の直接 URL や上部の検索ボックスを使う |
| 保存時に「Google authorization failed …」（unauthorized_client など） | 委任が未設定、クライアント ID の誤り、スコープ不足、反映待ち | 3.5 のクライアント ID とスコープを確認する。設定直後なら時間をおいて再試行する（最大 24 時間） |
| 「Google API … failed (403)」で API が無効という内容 | API が有効になっていない | 3.2 で該当する API を有効にする |
| 「主催者 … は … の Google Workspace ユーザーではありません」 | 主催者のメールのドメインが Workspace ドメインに含まれていない | 主催者を Workspace ユーザーにするか、3.8 のドメイン設定を確認する |
| 「Google Meet を開催するには主催者のメールアドレスが必要です」 | 主催者の Frappe ユーザーにメールアドレスがない | ユーザーにメールアドレスを設定する |
| 「この JSON はサービスアカウント鍵ではありません」 | OAuth クライアントの JSON など、別のファイルを貼り付けた | 3.4 で作成したサービスアカウント鍵を貼り付ける |
| 参加ログが取り込まれず、エラーログに「No Google Meet conference record yet」 | 会議がまだ行われていない、または記録の生成待ち | 会議の前なら正常な動作。最大 12 回まで自動で再試行する。会議を実施した後も続く場合は `meetings.space.readonly` の委任を確認する |
| 参加したのに「出席」が付かない人がいる | メールアドレスを特定できず、表示名も一致しない | 3.6 の連絡先共有を確認する。Frappe の氏名と Google の表示名をそろえる |
| 「AI 要約 / 会議メモ」に何も入らない | 予定終了時刻から間もない、「自動メモ作成」を開始していない、機能が無効、`drive.readonly` が未委任 | 予定終了時刻の 25 分後以降に再確認する。3.7 を確認する（取り込みは終了後 48 時間まで自動で再試行） |
| 文字起こしが取り込まれない | 仕様（「文字起こし」は取り込みの対象外） | 「自動メモ作成」を使う（3.7） |
| サービスアカウントの鍵を作成できない | 組織ポリシーによる制限 | 3.4 の注意を参照する |

## 6. セキュリティと運用

- **スコープは最小限に**：委任したスコープの範囲で全ユーザーのデータにアクセスできるため、本書に記載した以外のスコープは追加しません。
- **鍵の管理**：鍵ファイルは Frappe に登録した後に削除します。定期的に（例: 年 1 回や担当者の異動時）新しい鍵を作って差し替え、古い鍵は Google Cloud で削除します。
- **Google Cloud の権限**：プロジェクトのオーナーや編集者を最小限にし、鍵を作成できる人を限定します。
- **定期的な見直し**：管理コンソールのドメイン全体の委任の一覧を定期的に確認し、不要になった委任は削除します。
- **参加ログの利用目的**：Google は、Meet REST API を人事評価や成績の追跡に使わないよう定めています。出席の記録は会議運営の目的に限って使います。
- **退職・異動**：予定は主催者のカレンダー上にあるため、Workspace アカウントを削除する前に、その人が主催者になっている今後の社内ミーティングの主催者を変更します（主催者の変更は Seminar Manager が行います）。

## 7. 利用者の権限

一般のユーザーは、自分のミーティングの作成・招待・議事録の記入ができ、設定は変更できません。

| 操作 | System Manager / Seminar Manager | 主催者 | 主催者以外の参加者 | その他のユーザー |
|---|---|---|---|---|
| オンライン会議設定・Zoom ホストアカウントの変更 | ○ | × | × | × |
| 社内ミーティングの作成 | ○（主催者を指定可） | ○（主催者は自分のみ） | ─ | ─ |
| 閲覧 | すべて | ○ | ○ | ×（一覧にも表示されない） |
| 日時・参加者・議題などの編集 | ○ | ○ | ×（読み取り専用） | × |
| 議事録・アクションアイテムの編集 | ○ | ○ | ○ | × |
| 招待の送信 | ○ | ○ | ×（ボタンが表示されない） | × |
| 主催者の変更 | ○ | × | × | × |
